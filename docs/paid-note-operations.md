# 有料Note投稿の運用

## 実行と監視

- 通常の投稿は20時（日本時間）に実行する。2026年11月15日は20時から同時間帯の残り時間、5分間隔で457・478・479のみを対象に補完実行する。予定時刻前の記事は選ばない。
- GitHub Actionsの定期実行は遅延や欠落があり得る。時刻どおりの配信を保証するには、Actionsとは独立した監視で未実行・失敗・キュー滞留を通知する。
- 定期実行が起動しなかった場合は、実行履歴だけでなくNoteの公開済み記事と下書きも確認する。公開後に確認処理だけが失敗する場合があるため、無条件に再投稿しない。

## 投稿前の確認

- 異なるタイトルの記事と本文が完全に重複する場合は停止する。元原稿を確認し、正しい内容に修正するまで再実行しない。
- 同名の下書き・公開記事がある場合や、下書き一覧を全件確認できない場合は停止する。
- 見出し、本文、番号付きリスト、有料境界、価格、4個のハッシュタグを検証する。フォトギャラリーの検索結果から画像を選択する。

## 失敗時の復旧

- `pending_editor_url` がキューに残っている場合、記録された記事の公開状態と下書きを確認する。未確認のままこの値を消したり、新規記事として再実行したりしない。
- 公開済みの場合は、記事URL、価格、見出し、有料境界、タグを確認してからキューと投稿済み記録を整合させる。
- 下書きの場合は、内容と画像を確認して既存の下書きを使用する。下書きの新規作成や削除を自動で繰り返さない。
- ジョブの強制終了などでキュー更新の保存自体が失敗した場合も、同名記事と下書きを確認する。`pending_editor_url` だけを唯一の重複防止手段としない。

## テスト

依存関係とPlaywright Chromiumを導入後、`python -m unittest discover -s tests -p 'test_paid_note.py' -v` を実行する。ワークフローでも投稿前に同じテストを実行する。
